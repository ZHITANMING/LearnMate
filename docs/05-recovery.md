# 崩溃恢复与数据保全

这份文档写给「出事之后」的你：断电了、命令报错了、台账看着不对了。

知识库的第一条设计规则是 **先保住原文，再去调模型**（契约 §6.1）。所以无论崩在哪一步，
磁盘上都留着这份输入的规范化文本。这份文档告诉你：每个目录里是什么、什么能删什么不能删、
出事了跑哪条命令、跑完应该看到什么。

（有一种情况要单独说，见 §2：交进来的是 Word 文档时，`raw/` 里存的是**抽出来的文字**，
那份原始 `.docx` **不在知识库里**，只有你自己手上有。）

命令一律写成 `learnmate …`。在仓库里直接跑的时候，把 `learnmate` 换成
`node dist/main.js`（例如 `node dist/main.js doctor`）。

**这份文档只讲「出事了怎么办」。** 项目全貌与代码地图看 `docs/02-architecture.md`，
数据契约看 `docs/03-contracts.md`。本文里的每一条结论都能追到具体决定：
`docs/decisions.md` 的 D27（`--dry-run` 一个字节都不写）、D28（`q` 取消整批）、
D29（撞名整批不写）、D31（`draft/` 是模型返回什么的证据）、D34（发布过的提示词
文件永不删改）、D35（每个落到 `raw/` 的输入都会在台账里留下结局）、
D38–D41（`reprocess` 与裁定文件）、D42（`.docx` 抽成文本发生在任何写入之前，
落进 `raw/` 的是抽出来的文本）。

---

## 1. 先记住三句话

1. **`raw/` 里的原文是唯一的一份，永远不要删。** 它删了，你就再也没法重新整理那份输入，
   也没法回头核对模型理解得对不对。（输入是 `.docx` 时，这里存的是**抽出来的文字**；
   那份 Word 文件本身不在知识库里，这一节的备份与删除都碰不到它。）
   `draft/` 与 `resolutions/` 也别随手删——它们是 `reprocess` **不重新调用模型就能重来一次**的
   唯一依据（`resolutions/` 里还记着你写过的「更正为：…」，见 §2 的表）。
2. **台账（`ledger.jsonl`）是派生数据，可以重建；但「能重建」不等于「能还原」**——
   用量数字和历史会没（见 §4.2）。
3. **出问题先跑 `learnmate doctor`。** 它只看不写、不删任何文件，专门用来看「磁盘上有什么」
   和「台账里记了什么」对不对得上。

## 2. 知识库里有什么，什么能删

```
vault/
├─ notes/
│  └─ <slug>-<id8>.md            ← 笔记文件（唯一的人类可见产物）
└─ .learnmate/
   ├─ raw/<input_id>.txt         ← 规范化文本（按「输入」存；`.docx` 输入时是抽出来的文字）
   ├─ draft/<input_id>.json      ← 一次输入的全部草稿（NoteDraft 数组）
   ├─ resolutions/<input_id>.json ← 你在预览里对存疑项做的裁定（T13 起）
   ├─ ledger.jsonl               ← 台账
   ├─ quarantine/                ← 校验失败的现场
   └─ trash/                     ← 回收站
```

| 路径 | 里面是什么 | 能不能删 |
|---|---|---|
| `notes/<slug>-<id8>.md` | 整理好的成品笔记，**你的知识库本体** | **删了就真没了**（笔记文件本身没有第二份）。删完记得跑一次 `rebuild-index` 让台账跟上 |
| `.learnmate/raw/<input_id>.txt` | 规范化之后的原文，一次输入一个文件（输入是 `.docx` 时，里面是**抽出来的文字**，不是那份 Word 文件） | **永不删。** 唯一的一份原文，其它任何东西都替代不了。将来想换一套抽取规则重抽，只能重新 `add` 一遍，而那时原来那份 `.docx` 得还在 |
| `.learnmate/draft/<input_id>.json` | 模型这一次返回的全部草稿（**包括你按 `n` 跳过的那些**） | 谨慎。留着可以省掉一次模型调用（`reprocess` 就靠它）；删了只能 `--reanalyze` 重跑 |
| `.learnmate/resolutions/<input_id>.json` | 你在预览里对存疑项做的 `d`/`e` 裁定（**只记非「保留」的那些**） | 谨慎。删掉不等于「笔记坏了」，但下次 `reprocess` 会按「没有任何裁定」重渲染，你写的那些「更正为：…」会消失。想恢复就重新 `add` 一遍并在预览里再答一次 |
| `.learnmate/quarantine/<input_id>.json` | 模型输出不合契约的现场：每一次的原始产出 + 一句话说明 | 可以删，它只用于事后诊断 |
| `.learnmate/trash/` | 被换掉的旧笔记（T13 起由 `reprocess --reanalyze` 搬进来，文件名与原文件相同，撞名加 `.<n>`） | 可以删——它本来就是回收站。删之前先看一眼里面是不是你还要的东西 |
| `.learnmate/ledger.jsonl` | 台账，一行一个 JSON，**只追加** | 不要手工编辑。整份删掉可以重建，但会丢东西（§4.2） |

**一次输入 = 一个 `input_id`。** 一次输入可能拆出十几条笔记，但 `raw/` 与 `draft/`
各只有一份，都叫 `<input_id>.txt` / `<input_id>.json`。想从一条笔记找到它的原文，
看笔记 frontmatter 里的 `input_id`，再去 `raw/` 里找同名文件。

## 3. 崩溃之后：你会看到什么 → 跑什么 → 期望看到什么

这张表是契约 §6.3 的用户版。写入顺序固定是
`raw/` → `draft/` → `notes/`（仅确认后）→ `ledger.jsonl`，所以「崩在哪一步」是可以从
磁盘上看出来的。

| 崩在哪 | 你会看到什么 | 跑什么命令 | 期望看到什么 |
|---|---|---|---|
| 第 1 步之后（原文刚写完） | `raw/<input_id>.txt` 存在；`notes/` 没有新文件；台账里可能有一行 `llm_error` 或 `validation_failed` | 直接重跑 `learnmate add <同一个文件>` | 指纹还没记账，正常重跑一遍。同一份输入不会因此多出两份笔记 |
| 第 2 步之后（草稿也写完了） | `raw/` 和 `draft/` 都在，`notes/` 没动静 | `learnmate reprocess --input <台账里那一行的 input_id>`（**默认不调模型、不需要 API Key**）。想先看看会写什么就加 `--dry-run` | 笔记正常产出，`draft/` 一个字节都不动。走这条路的 `updated`/文件名如果与你想的不一样，多跑几次也不会重复写（内容没变就零写入） |
| 第 3 步写到一半（笔记写了一半） | `notes/` 里多了几个文件，但台账里的行数对不上 | `learnmate rebuild-index --dry-run` 看一眼 → `learnmate rebuild-index` | 台账按 `notes/` 补全。**不会**动你的笔记文件 |
| 第 4 步写到一半（台账写了半行） | 台账末尾有读不出来的半行；`doctor` 会报「台账坏行」 | `learnmate rebuild-index` | 坏行被抹掉（先备份的话见 §6），其余记录原样留下 |
| 任意时刻（只要命令已经走到写 `raw/` 这一步） | —— | —— | **这份输入的原文一定还在 `raw/` 里**。唯一的例外是抽取失败（退出码 2，例如 `.docx` 读不出来）：那时一个字节都没写，你的原始文件也原封不动 |

崩溃之后的通用动作，按顺序：

```
learnmate doctor                      # 只看不写：先看清现场
learnmate rebuild-index --dry-run     # 只报告：台账本该长成什么样
learnmate rebuild-index               # 确认之后再真的写
```

## 4. 六个常见事故剧本

### 4.1 「台账里少了几行」

**症状**：`doctor` 的体检一节报 `notes 与台账 ✗ 对不上`，或者报有几个「孤儿原文」。

**为什么会有**：`add` 是分步写盘的（原文 → 草稿 → 笔记 → 台账）。在最后一步之前崩掉，
磁盘上就有文件、台账里就没有对应的行。T11 之前，有五种结局（模型输出不合契约、调用模型
失败、模型说没有可整理的、用户取消整批、文件名撞名）根本不会在台账里留下任何一行——
那些输入就成了「孤儿」。

**怎么办**：

```
learnmate rebuild-index --dry-run
```

它会告诉你：`✓ 沿用` 几条、`+ 新造` 几条、`- 剔除` 几条、`· 历史` 几条。看清楚之后再：

```
learnmate rebuild-index
```

**期望**：台账和 `notes/` 一一对应。再跑一次 `--dry-run` 应该只报「沿用」，没有新增。

**注意**：重建只读 `notes/`，不会删你的笔记文件。

### 4.2 「台账被删了 / 坏掉了」

台账是**派生数据**，删掉它不会让笔记消失，跑一次 `learnmate rebuild-index` 就能从
`notes/` 重建。**但重建不等于还原**（契约 §9.2）：

- **重建不回来的**：`tokens_in`、`tokens_out`、`latency_ms`、`uncertain_total`、
  `uncertain_kept` —— 一律补 `0`。笔记文件里从来没有这些字段，这个信息在写下的那一刻
  之后就永久消失了。补 0 的意思是「不知道」，不是「它们是零」。
- **也回不来的**：历史行。`cancelled` / `empty` / `llm_error` / `validation_failed` /
  `unsafe_write` 这些「这次输入没产出笔记」的记录，**只存在台账里**。契约 §9.1 说的
  「非 `ok` 原样保留」只适用于台账还在、只是缺几行的情况；**整份台账删掉，这些历史就
  一起没了**，而且没有任何文件能把它重建出来。

所以：**台账丢了不算灾难，但那些用量数字和「哪几次输入没整理成」的记录就是真没了。**

### 4.3 「模型老是返回不合契约的东西」（退出码 3）

**症状**：命令退出码 `3`，日志里有「现场已保存」。

**怎么办**：打开现场文件看模型到底返回了什么：

```
type vault\.learnmate\quarantine\<input_id>.json
```

里面有几个字段：

- `message` —— 一句话说明这次为什么不合契约（`doctor` 也会打出来）；
- `attempts` —— 重试了几次；
- `raw_outputs` —— **每一次**的原始产出。第一次和第三次的差别往往就是全部线索。

**期望**：看完就知道是模型跑偏了，还是提示词需要改。原文还在 `raw/<input_id>.txt`，
换好模型或提示词之后可以拿同一份原文重跑。台账里会有一行 `validation_failed`（T11 起）。

**改提示词前先读 `decisions.md` 的 D34**：`prompts/analyze.v1.md` 与 `analyze.v2.md` 都是
**发布过的**提示词文件，**永不删改**——它们各自对应台账里已写下的 `prompt_version`，改了就无法
解释历史笔记是怎么来的。要调整就新增一个版本文件，再把 `learnmate.config.json` 的
`promptVersion` 指过去（`doctor` 会告诉你当前用的是哪一份、存不存在）。
注意：**提示词模板内容坏掉**时（`add` 在组装系统消息那一步抛 `UsageError`，**退出码 2**），
`raw/` 已经落盘却**不会**在台账里留下任何一行——这是契约 §9.3 不变量的一个已知例外，
记为技术债 **TD14**，不是你的操作失误。`doctor` 会先把「提示词文件在不在、读不读得出来」
报给你，所以先跑它。

### 4.4 「出现了孤儿原文 / 孤儿草稿」

**症状**：`doctor` 的体检一节报「孤儿原文」和「孤儿草稿」。

**含义**：`raw/<input_id>.txt` 在，但台账里**没有任何一行**带这个 `input_id`。
这只可能来自三种情况：T11 之前的旧版本、台账被删过、台账被手工改过。

**怎么办**：

```
learnmate doctor
```

看得到就够了。**不要手工删 `raw/`。** 体检会一直把它报出来——这是诚实的代价：
自动删用户数据不是 `doctor` 该顺手做的事（见 `decisions.md` 的 D35）。
T11 之后的输入不会再产生新的孤儿。

### 4.5 「想重新整理某一条笔记」

T13 之后有这条命令了，而且**默认不调模型、不需要 API Key**：

```
learnmate reprocess                                  # 先看有哪些输入可以重处理（退出码 2）
learnmate reprocess --input <input_id> --dry-run     # 只看会写什么，一个字节都不写
learnmate reprocess --input <input_id> --yes         # 真的重渲染
learnmate reprocess --note <26 位笔记 id>            # 只重渲染这一篇
```

三条使用建议：

1. **先 `--dry-run`。** 它会告诉你哪几篇「未变化」（内容与盘上逐字节相同，一个字节都不会写）、
   哪几篇会被改写。看到「全部未变化」说明你的笔记已经是最新的，什么都不用做。
2. **不加 `--yes` 就逐条问你**（和 `add` 一样的 `[y]/[n]/[a]/[q]`）。`reprocess` 会覆盖真实笔记
   文件，而 `vault/` 不在 Git 里（D8），没有版本可回退——**第一次跑先别加 `--yes`**。
3. **想真正重新分析就用 `--reanalyze`**（这一步会调用模型、要 API Key）：它把 `raw/<input_id>.txt`
   当一次全新的输入再跑一遍，产出一批新笔记，而**旧笔记会被搬进 `vault/.learnmate/trash/`**
   （不是删掉，能捞回来）。中途按 `q` 取消的话，旧笔记原封不动。

**台账不会因为 `reprocess` 而改变。** 重渲染不改变「这次输入的结局」，所以它一行都不写；
要刷新台账里的派生字段（标题、标签、路径），跑：

```
learnmate rebuild-index --dry-run    # 先看
learnmate rebuild-index              # 再写
```

### 4.6 「重渲染失败之后怎么办」

`reprocess` 是**逐条写**的，没有整体事务。所以「写到一半崩了」是有可能的：`notes/` 里前几篇是
新的、后面几篇还是旧的（或者在 `--reanalyze` 的情况下，旧的在 `trash/` 里）。**不需要特殊的补救
动作，重跑一次就行。**

- **直接重跑同一条命令。** `reprocess` 是幂等的：已经写好的那几篇会被认成「未变化」，
  一个字节都不会再写——这正是它设计成逐字节比较的原因（契约 §12.3）。
- **如果是 `--reanalyze` 崩在「搬完旧的、还没写完新的」之间**：那时 `notes/` 缺这一批，
  但它们都在 `vault/.learnmate/trash/` 里。
  - 想就地恢复：把 `trash/` 里那几个文件**手工搬回 `notes/`**（拖回去就行），再跑
    `learnmate rebuild-index`。
  - 想继续重来：直接重跑 `reprocess --input <新的 input_id> --reanalyze`（新 `input_id`
    在崩溃前的输出里，也能从 `draft/` 里最新那个文件看出来）。
- **整批拒绝（撞名）时不会有半成品**：`reprocess` 在写任何文件**之前**就把全部目标文件名算
  一遍，撞名则整批不写、退出码 3。看到「碰头」那句话说明**一个文件都没动**。
- **不要手工删 `draft/` 或 `resolutions/` 来「重来一次」。** 删了 `draft/` 就只能重新花一次
  模型调用；删了 `resolutions/` 会丢掉你写过的「更正为：…」（§2 的表）。

## 5. 不要做

- **不要手工编辑 `ledger.jsonl`。** 它是只追加的历史。改坏一行，它就变成「读不出来的
  坏行」，而下一次 `rebuild-index` 会把它静默抹掉——你以为改好了，其实是被删了。
- **不要删 `raw/`。** 那是原文唯一的一份（§1）。
- **不要在没有备份的情况下删 `draft/`。** 它是「不重新调用模型就能重来一次」的唯一依据。
- **不要在 `notes/` 里手工挪动笔记文件。** 台账按 `note_path` 认文件；挪完了
  `doctor` 会报对不上，得跑一次 `rebuild-index` 才会刷新成新路径。
- **不要把 `vault/` 交给 Git 之外的同步工具去「合并冲突」。** 台账是追加式的文本文件，
  冲突合并会写出两份历史。真出冲突了：留一份 `ledger.jsonl` 备份，然后 `rebuild-index`。

## 6. 备份

`vault/` **不在 Git 里**（已在 `.gitignore` 中，见 `decisions.md` D8）。它不会自己留底。

按代价从低到高：

| 备份什么 | 留住了什么 |
|---|---|
| 一个 `ledger.jsonl` 的副本 | 用量数字 + 历史行（这两样**只有它记得**） |
| 整个 `.learnmate/` 目录 | 加上原文 `raw/`（不可再生）与草稿 `draft/` |
| 整个 `vault/` 目录 | 再加上成品笔记 |

`notes/` 是你的知识库本体，值得单独同步或备份。但请记住：**`raw/` 才是不可再生的那部分**——
笔记可以由模型再生成一次，原文不能。（输入是 `.docx` 时也一样：库里只有抽出来的文字，
想换一套抽取规则重来一次只能重新 `add`，而那时你手上得还留着那份 `.docx`。）

## 7. 这一节能自己验证

```
learnmate doctor
```

反复跑它不会改变任何东西（doctor 只读）。它也是唯一一条「知识库坏掉时仍然能用」的命令：
配置不对它会告诉你哪一行不对；知识库对不上它会告诉你差在哪、该跑哪条命令。
