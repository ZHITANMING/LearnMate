# 01 · 项目简介

> 这份文档回答一个问题：**LearnMate 到底要干什么，以及 v0.1 不干什么。**
> 数据结构长什么样，见 [03-contracts.md](03-contracts.md)；模块怎么分，见 [02-architecture.md](02-architecture.md)。

## 一句话

LearnMate 是一个**个人 AI 知识助手**：你把随手记的学习笔记丢给它，它整理成结构化的
Markdown，存进你自己的知识库。

## 先纠正一个定位问题

「输入文本 → AI 整理成 Markdown」这个动作本身**没有任何护城河**。任何一个聊天窗口
都能做，而且明天会有更好的模型免费做。

真正会随时间升值的东西是**知识库本身**——半年后你攒下的那几百条结构化笔记。所以
LearnMate 的定位不是「一个 AI 笔记工具」，而是：

> **给你的笔记建一个不会腐烂的归档系统。AI 只是录入员。**

这个定位决定了两件事：

1. **录入质量比录入速度重要。** 一次整理得不好，你会永远不再打开那条笔记，而且
   知识库里多了一份噪音。宁可慢，不可脏。
2. **格式的稳定性比格式的漂亮重要。** 如果 100 条笔记有 30 种不同的结构，这个知识库
   就已经死了——它无法被排序、筛选、检索，也无法在半年后被你重新理解。

## v0.1 做什么

只做这一条闭环，做扎实：

```
文本输入  →  AI 整理  →  Markdown 生成  →  保存知识库  →  用户查看
```

输入是**纯文本**（你自己敲的、从文档里复制粘贴的）。v0.1 只有这一种；v0.2 起 `add` 也直接
收 `.docx`（先抽成文本，之后走的路完全一样，见 D42）。

## v0.1 不做什么

| 不做 | 打算什么时候做 |
| --- | --- |
| 图片 OCR | v0.2 |
| PDF 解析 | v0.2 |
| Word 解析 | v0.2 |
| 语义检索 / 向量数据库 / RAG | v0.3 |
| 知识图谱、笔记关联 | v0.4 |
| 自动生成题目、学习计划、自动提醒 | 未排期 |

**唯一的范围修正：基础全文检索在 v0.1 就应该能用。** 但这不是一个功能，而是一个
布局要求——只要笔记是一个个独立的 `.md` 文件、放在一个目录里，用编辑器的「在文件夹中
搜索」就已经能全文检索了。不需要为此写任何代码。

## 最大的风险不是被推迟的功能

上面那张「不做」表里的东西，晚点做都不会出事。真正的风险在**被包含进来的那个模糊项**：
「AI 理解内容」。

「理解」没有形状。如果不定死 AI 必须产出什么，那么：

- 同一段笔记跑两次，出来的结构不一样；
- 50 条笔记之后，每条都有自己的小结构，知识库退化成噪音；
- 你想改一改展示方式，得重新调模型。

所以这个项目的核心命题是一句话：

> **schema 就是产品。**

把「AI 整理」这件看不见的事，压缩成一个**固定的、可校验的数据结构**，是这个项目
技术上最重要的一步。这也是为什么有一份专门的 [03-contracts.md](03-contracts.md)。

## 第二大的风险：只写不读

个人知识管理工具的头号死法不是「功能不够」，而是**变成一座只写不读的坟墓**。

v0.1 不打算做复习闭环（间隔重复、每日回顾那些），但**必须现在就留一个钩子**：
每条笔记的 frontmatter 里有一个 `status` 字段（`inbox` / `processed` / `reviewed`）。
现在它只是被写进去、没人读；等到将来真要做「回顾」功能时，历史笔记不用迁移就能用。

留这个钩子的成本是 0，不留的代价是全部笔记迁移一遍。

## 什么算 v0.1 成功

1. 粘一段真实的课程笔记进去，能得到一份**你愿意留着**的结构化 Markdown。
2. 这条笔记在你自己的编辑器里能正常打开、能搜到。
3. **内容没有被弄丢，也没有被编造。** 这是用户最不能接受的失败方式，优先级高于
   「整理得漂亮」。
4. 整个流程失败时，**原始文本一定还在**。

## 版本路线

| 版本 | 主题 | 会新增什么 |
| --- | --- | --- |
| **v0.1** | 基础知识整理 | 文本输入、AI 整理、Markdown 生成、知识库、查看 |
| v0.2 | 多格式输入 | 图片 OCR、PDF、Word。**不改变核心整理流程**。其中 Word（`.docx`）已在 v0.2 第一步落地（见 D42） |
| v0.3 | 智能查询 | 搜索、向量索引、RAG |
| v0.4 | 知识网络 | 笔记关联、知识图谱 |

每一版都只加「入口」和「出口」，中间的整理流程和数据结构保持不变。这是
[02-architecture.md](02-architecture.md) 里分层设计的全部目的。
